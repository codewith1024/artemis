## 代码与契约

### 显式开启，不能误入库

- 新增 `--observe-exceptions`，只允许与 `--capture-only` 一起使用，不能与 `--commit` 同用，也不能误走数据库 dry-run。
- 入口参数验证早于采集、建目录或数据库连接。
- 失败后的恢复/重启命令保留两个安全开关。
- 异常观测产物带 `capture.observation_contract='v1'`；终态声明 `observation_complete=true`、`business_complete=false` 和逐条异常清单。
- `require_complete=True` 仍要求普通 success 与原平台目标数，绝不由异常态放行。

### 渠道未知必须有证据

- 只有观察到完整渠道表至“其他信息”边界，才能把某个 SKU 的缺行记录为 `row_absent`。
- 整块渠道缺失、尚未读到表尾、同规格歧义、重复价格库存等仍然失败，不自动当未知完成。
- 元数据保存在 SKU sidecar 的 `observations[父卡序号][SKU][渠道]`，包括区块原状态、原因和详情 XML 路径/哈希。
- 本地门禁逐页验证哈希，并独立复解析原始 XML，确认区块真实存在、该规格行确实不在、表尾已观察到。不能只写一个 `row_absent=true` 就过关。
- SKU 子行仍严格保持 40 列，不把元数据混进业务字段。

### 平台计数差不再用集合自证

- 采详情前独立预扫当前列表并回顶。
- 原始 XML 卡容器生成有序卡清单，检查相邻屏边界重叠、多重卡身份、平台标题数稳定、末两屏一致与 App 读尽标记。
- 同名同规格不能简单用 set 合并；证据顺序或出现次数无法证明时拒绝。
- 终态门禁重新读取逐屏文件、验证哈希、重新按卡容器计算卡数，并与采集 CSV 身份多重集比较。
- 平台原数仍存在 `scope.expected_product_count`，可见卡数另存异常条目，没有把 52 改为 51、44 改为 43。

## 真机中发现并修复的边缘行为

首轮预扫发现：屏幕下沿仅露标题的下一张卡，以及原生 `ProgressBar`/“正在加载更多”提示，被原始容器提取器误判为缺规格商品。已按实时 XML 结构区分边缘残片和加载节点；相邻页仍必须提供完整卡片并通过连续性核对。

首轮因此失败并保存工件，不被当成通过。修复后重新预扫及全详情采集，得到上述完整异常观测终态。相关回归测试已补。

## 尚未做与边界

- **没有跑全店长轮次。** 本轮真机验证范围是猫粮和猫零食两个类目。
- category 分片器能将已验证的异常观测作为分片终态收口，免去无意义 20 次重试；但跨分片“异常观测聚合”本轮未实施，聚合遇异常片会明确拒绝并列出清单，不会产出假成功聚合。
- 原始列表预扫与详情采集不是同一时刻；若商品标题、规格、条码或数量中途变化，身份对账会拒绝，需重新观测，不会混合后硬标完成。
- 平台后台多计 1、某 SKU 不列出某渠道的精确后台原因仍未知；本地契约只诚实记录 UI 已观察事实。
- 未实现任何未知状态入库映射，多 SKU 或异常态入库均被拦截。
