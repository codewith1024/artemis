# 美团采集数据 → 新库 字段来源映射（开发内部用，历史 v2）

库：`192.168.100.200` / `retail_price_snapshot`（表结构 v2，见 `retail_price_snapshot_schema.sql`）

两种采集方式：

| capture_method | 来源 | 写哪些表 |
|---|---|---|
| `h5_api_replay` / `h5_passive` | `store_capture/` 下的接口 JSON（`food` 门店菜单接口、`quickbuy/v1/poi/sputag/products` 分类商品接口） | 全部表 |
| `h5_scroll_text` | meituan-store-capture skill 的运行目录（`manifest.json`、`text/NNNN.txt`、`products.csv`） | 除 `fact_store_spu_category_rel`、`fact_store_sku_price_snapshot`、`dim_store_source_id` 以外的表 |

2026-10-08 已用真实数据在线上库做过一次完整写入测试（事务内写入后回滚）：满佳喜 501 屏 1,053 个商品、乐购达休闲食品 788 SPU / 800 SKU 全部写入成功，测试脚本 `v2_load_test.py`（同目录）可作为入库程序的参考实现。

## 通用规则

- 平台用 `-1` / `-1.0` / `"-1"` 表示“无”，入库写 NULL。
- 金额单位是元，原样写入 DECIMAL(18,4)。
- 时间都是 Asia/Shanghai；`snapshot_hour` = 本次门店采集开始时间取整到小时。
- 哈希统一用 SHA-256 十六进制小写。JSON 先 `json.dumps(obj, ensure_ascii=False, sort_keys=True, separators=(',', ':'))` 再算。
- 一次门店采集先写 `store_snapshot`（status=running），全部写完再改成 success / partial / failed。视图 `v_store_spu_price_latest` 只取 success / partial。

### listing_key（商品定位键）

| 场景 | 规则 |
|---|---|
| SPU 表，接口数据 | `sha256('spu:' + source_spu_id)` |
| SPU 表，滚屏数据 | `sha256('name:' + 商品名原文)`；同一次采集里第 N 个（N≥2）同名商品用 `sha256('name:' + 商品名 + '#' + N)` |
| 匹配表，接口数据 | `sha256('sku:' + source_sku_id)`，listing_type = sku |
| 匹配表，滚屏数据 | `sha256('name:' + 商品名原文)`，listing_type = name |

滚屏数据同名商品按 `products.csv` 里的出现顺序编号（解析脚本已经按价格、规格、库存单位把同名的不同商品分开了，实测 1,053 个里有约 10 组）。

### category_key（类目定位键）

有平台 tag 时用 tag；滚屏数据只有类目名，用 `'name:' + 类目名`。

## 二、滚屏数据（meituan-store-capture）

一个运行目录记作 `run`；大店分段采集的多个运行目录合并成一个 `store_snapshot_id`。

### store_snapshot

| 列 | 来源 |
|---|---|
| capture_method | `h5_scroll_text` |
| device_id | `manifest.device` |
| started_at / finished_at | `manifest.started_at` / `manifest.finished_at`（分段时取最早 / 最晚） |
| stop_reason | `manifest.stop_reason`（分段时取最后一段） |
| screen_count | `len(manifest.shots)`（分段时相加） |
| evidence_uri | 运行目录（或上传到 NAS / 对象存储后的位置） |
| store_name | `text/0000.txt` 中「评分…」上一行（解析脚本的 `store_name()`） |
| store_score | 「评分4.3」→ 4.3 |
| delivery_time_text / avg_delivery_minutes | 「配送约64分钟」/ 64 |
| bulletin | 「公告：…」去掉「公告：」 |
| captured_spu_count | `products.csv` 行数 |
| covered_categories | 没采全时填采到的类目名，`|` 分隔 |
| status | 「页面已到底」→ success；「达到最大滚动次数」等 → partial |

### fact_store_promotion_snapshot

`text/0000.txt` 里公告之后、「搜索店内商品」之前的每一行（同文案合并，`promo_count` 记出现次数）：

| 文案 | promo_type | threshold_amount | discount_amount |
|---|---|---|---|
| `199减20` | full_reduction | 199 | 20 |
| `新客减1` | new_customer | 0 | 1 |
| `领2元商品券` | coupon | NULL | 2 |
| 其他 | other | NULL | NULL |

### fact_store_category_snapshot

「搜索店内商品」之后的类目栏（解析脚本 `sidebar_categories()`，按出现顺序去重）：category_key = `name:类目名`，category_order 从 1 开始。滚屏数据读不到商品所属类目，所以 `captured_spu_count` 为空，也不写 `fact_store_spu_category_rel`。

### store_raw_data_snapshot（一屏一行）

| 列 | 来源 |
|---|---|
| record_type | `screen` |
| screen_index | `manifest.shots[i].index` |
| evidence_uri | `manifest.shots[i].shot`，如 `shots/0012.png` |
| collected_at | `started_at + shots[i].elapsed` 秒 |
| raw_data | `{"lines": text/NNNN.txt 各行, "screen_lines": text/NNNN.screen.txt 各行, "video_time": shots[i].video_time}` |

实测一屏平均约 23 KB，最大约 72 KB；500 屏约 11 MB。

### fact_store_spu_price_snapshot（`products.csv` 一行 = 一个商品卡片）

| 列 | CSV 列 / 规则 |
|---|---|
| listing_key | 见上文 |
| product_name | 商品名 |
| front_display_price_amount | 售价 |
| price_condition | 优惠条件（第1件、前3件） |
| is_from_price | 起价 = 是 → 1 |
| user_final_price_amount | 到手价 |
| original_price_amount | 原价 |
| multi_buy_text / multi_buy_quantity / multi_buy_unit_price_amount | 多件价「买2件¥15.8/件」→ 原文 / 2 / 15.8 |
| discount_text / limit_purchase_quantity | 折扣「0.02折 限1份」→ 原文 / 1 |
| promo_remaining_text | 优惠余量 |
| month_sales_text / month_sales_qty | 「月售」+ 月售 / 月售去掉 + |
| want_to_buy_count | 想买人数 |
| praise_rate_pct | 好评率去掉 % |
| stock_text / stock_quantity / stock_unit | 库存「3份」→ 原文 / 3 / 份（库存多时页面不显示，为空） |
| has_multi_spec | 多规格 = 是 → 1，否则 0 |
| other_text | 其他 |
| sale_status | available（已售罄的卡片解析脚本会标出来时写 out_of_stock） |

### map_source_sku_standard

每个不同的商品名一行，listing_type = name，product_name 填原文。没有条码，只能按名称 / 规格匹配或人工复核。

## 数据注意点

- **活动价受 A/B 实验影响**：接口 `ai.ab_test` 里有 `price_new4`、`xiangou_price` 等实验分组，不同账号看到的价格可能不一样。事实表没有单独存这个字段，原始 JSON 里有，排查价格异常时去原始表查。
- **“第1件”价格不是常规售价**：滚屏数据约 72% 的商品主价格是「第1件」限定价，做常规价对比时要看 `price_condition`，优先用原价或剔除。
- **“神价”“活动”两个类目翻页有问题**：服务端每一页都返回同一批 20 个商品（见 `final_fetch.py` 里的 `DONE_CATS`），入库时靠唯一键去重就行。
- **现有 `store_capture/` 数据**：实际是多轮采集叠在一起（被动录制 + 两轮重放），入库时建议按采集轮次拆成不同的 `store_snapshot_id`，不要合成一个版本。
